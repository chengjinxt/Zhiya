# 刷机原理

## 一句话

刷机原理上就是重装操作系统，但 Android 的"重装"粒度更细：Windows 是一整块 C 盘镜像写过去，Android 是按几十个分区逐个烧写镜像。

## 与重装 Windows 的区别

| 对比项 | 重装 Windows | 安卓刷机 |
|---|---|---|
| 操作对象 | 整盘或单个分区（C 盘） | 按分区逐个烧写（boot、system、vendor、userdata……） |
| 分区表 | 用户可自行划分 | 出厂定死，写在分区表镜像里，用户一般不动 |
| 引导 | BIOS/UEFI + BCD/GRUB | Boot ROM（芯片固化）→ bootloader → boot.img（内核） |
| 安装环境 | WinPE / 安装 U 盘 | Recovery 模式 / Fastboot 模式 |
| 用户数据 | 可保留 D 盘 | userdata 分区独立，刷机可选择不清空 |
| 签名校验 | 基本没有 | AVB 校验链：bootloader 验每个分区的签名；解锁 = 关掉这道检查 |

## 启动链条

```
Boot ROM（芯片内固化，不可改）
  → XBL/ABL（bootloader，负责 fastboot 模式）
    → boot.img（Linux 内核 + ramdisk）
      → init 进程
        → system 分区（Android 框架层）
```

## 开机 logo 的三个阶段

logo 会出现三次，分属不同阶段，修改难度不同：

1. **第一屏 logo**：bootloader 阶段显示，存放在 `splash`/`logo` 分区的一张 raw 图片。可替换：重打包 logo.bin 烧入对应分区。
2. **开机动画**：内核起来后播放，`/system/media/bootanimation.zip`（PNG 序列打成的 zip）。**最容易换**，替换文件即可。
3. **锁屏/桌面**：进系统后，属 APP 层。

## 解锁 bootloader 的本质

= 关掉主板的 Secure Boot。解锁后可向任意分区写入任意内容；代价是清空数据、失去保修、AVB 校验链断开。
