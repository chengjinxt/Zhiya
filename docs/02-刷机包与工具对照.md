# 刷机包类型与工具对照

## 刷机包类型

| 类型 | 内容 | 类比 | 说明 |
|---|---|---|---|
| 官方线刷包 | fastboot 包：全部分区镜像 + 刷机脚本 | 纯净安装 ISO | 最完整，救砖用它 |
| 官方卡刷包 | recovery zip：只更新 system/vendor 等少数分区，保留数据 | Windows 累积更新 | OTA 增量更新走的就是这个通道 |
| 第三方 ROM（如 LineageOS） | 完整的 system 替代品，基于 AOSP 编译 + 机型适配层 | 第三方精简系统 | 给孩子用只选官方维护的包 |
| GSI（通用系统镜像） | Project Treble 后的产物，一个 system.img 通刷所有支持机型 | Windows 通用镜像 + 自动装驱动 | 老机器多不支持，指望不上 |
| 内核包 / Magisk 模块 | 只动 boot 或 system 一小部分 | 系统补丁 / 驱动 hook | Magisk = 给 boot.img 打补丁，root 由此而来 |

## 各阶段工具对照（Android ↔ Windows）

| Android 工具 | 作用阶段 | Windows 对应物 |
|---|---|---|
| fastboot 模式 | BIOS 级烧录：`fastboot flash boot boot.img` 逐分区写 | diskpart + dism / ghost |
| Recovery 模式 | 在该环境下 `adb sideload update.zip` | WinPE 下运行安装包 |
| MiFlash / Odin / QFIL / SP Flash Tool | 厂商一键烧录，底层仍调 fastboot/9008 等协议 | rufus 写盘 + 自动分区 |
| 高通 9008（EDL）模式 | 比 fastboot 更底层的烧录，砖机最后手段 | Intel ME 级别的底层刷写 |
| Magisk | 给 boot.img 打补丁，获得 root | 给 Windows 内核打 hook 驱动 |

## 都是基于 Google 源码编译的吗？

AOSP（Android 开源项目）是地基，但**没有任何一台真机跑的是纯 AOSP**。

```
真机系统 = AOSP（开源） + HAL（硬件抽象层） + 闭源驱动 blob（高通/联发科/相机厂商提供，只有二进制）
```

第三方 ROM 的真相：拿 AOSP 源码编译 system 部分，驱动 blob 从官方包里提取照搬。维护一个机型的核心工作是写 **device tree**（设备树：描述分区布局、驱动组装方式），blob 本身是黑盒。这就是只有热门机型有人维护的原因。
